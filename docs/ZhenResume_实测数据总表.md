## 2. 两代 Agent 路线的干净对比（同一模型）

> 两臂都在 `qwen3.8-max-0902` 上跑完 32 份；期间清空过跨模型缓存，表内数字可比。

| 维度 | P2-a 单次调用 + 工具 | P2-c LangChain Agent 循环 | 判断 |
|---|---|---|---|
| 排序相关性 | **+0.847** | +0.755 | ❌ Agent 更差 |
| 假差距 recall | 88.9% | **90.3%** | ✅ 略升 |
| 误判真差距 | 49 | **38** | ✅ 降 22% |
| 模型往返 | 2 | 9.3 | 4.7× |
| tokens/份 | ~3,000 | 33,722 | 11× |
| 成本/份 | ¥0.005 | **¥0.08** | 16× |
| 延迟/份 | 7s | 35s | 5× |

**结论**：在"关键词级假差距判定"这一子任务上，**Agent 循环没有证明自己更优**——
它把 precision 的噪声换成了 recall 分布的不均匀；因此**不接进评分链路**。
（有效结论；对应 `P2-b §6.4`。）

## 3. Agentic RAG（P3）：固定检索 vs Agent 自主多轮

同一批 10 份简历、同一 JD、16 切片知识库、同一套 gold 标注；两轮独立运行结论一致。

| 指标 | 固定检索（现状） | Agent 多轮检索 | 判断 |
|---|---|---|---|
| **gold 覆盖** | 89.2%（修复前 61.7%） | **93.3%**（修复前 61.7%） | ✅ +4.1pp |
| 单案例胜 / 平 / 负 | — | 3 / 6 / 1 | ⚠️ 有增益但不稳定 |
| 至少引用到 1 条 gold | **0%（无引用能力）** | **100%** | ✅ 能力从无到有 |
| 引用逐字校验通过 | — | 97–99% | ✅ 引用可信 |
| 检索轮次 | 1 | 3.9（预算上限 4） | — |
| 成本 / 延迟（每份） | ≈0（仅 embedding） | **¥0.094 / 28s** | 约 20×，绝对值小 |

**为什么不是压倒性更好**：知识库只有 16 个切片，固定检索 `top_k=5` 已覆盖 31% 库容量；
增益集中在"需要 `resume_template`（表达/量化）依据、而 JD 驱动 query 不指向这些文档"的案例。

**评测中发现并修复的真实 bug**：
> `rag.search(role_family=...)` 原为硬过滤 `WHERE role_family = 目标族`，
> 而 `compliance/industry/resume_template` 三类文档的 `role_family='general'` →
> 传了 `role_family` 就**永远**检索不到这三类知识。
> 且它伪装成模型问题（Agent 如实报"该方向未命中"）。
> 修复为 `role_family IN (目标族, 'general', NULL)`。

## 4. 报告质量缺陷实测（存量数据扫描）

扫描本地库 **127 份报告 / 850 条建议**：

| 检查项 | 结果 | 说明 |
|---|---|---|
| "改写既有经历"类建议 | 166 条 | 排除"建议补词"模板类 |
| 改写句中**出现原文没有的量化数字** | 17 条 / **10.2%** | 例：原文无 99.99%，改写句写出"可用性达 99.99%" |
| 自相矛盾案例 | 存在 | 发现项本身是"绝对化表述风险/数据过于完美"，改写却新增了更完美的数字 |

**结论**：这是确定性可修的缺陷（改写句中的数字必须可追溯到原文，否则替换为 `[补充：数据]` 占位符），
不构成"需要 Agent"的理由——符合项目原则：**Agent 必须有规则做不到的价值才上**。

## 7. 诚实的负面结论清单（必须保留，防止过度宣传）

1. **关键词级假差距判定**：Agent 循环（P2-c）排序更差（+0.755 vs +0.847），成本 16× → **不上**。
2. **多轮检索**：gold 覆盖只从 89.2% → 93.3%，且单案例会回退（3 胜 6 平 1 负）→ 收益有限，
   真正价值在"结论级引用 + 可解释的检索决策"（能力从无到有），不是检索广度。
3. **绝对分数会低估**：语义救回幅度在四档质量上几乎一致（+7~+10），所以它修正"分数低估"（如 ATS 73→88），
   但不改善排序——排序由规则覆盖率主导。
4. **HR 端不做 Agent 化**：并发已把时间压到 3.3s/份量级，Agent 化只会加成本。
5. **公平性断言 flaky**：不是功能缺陷，是验收标准过严（100% 二元断言），建议改为 ≥99.5% + 硬断言"受保护内容不得进报告"。
